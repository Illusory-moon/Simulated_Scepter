# 倒计时模拟器：修正结论与模型边界

## 当前在线链路

生产环境与 GUI 共用 `tool/countdown_evaluator.py`；
`test/countdown_backend.py` 仅保留兼容转发：

1. 环境先给出本次实际效果；
2. 玩家或策略选择 `keep / cheat / reroll`；
3. `reroll` 先扣资源，再产生新的实际效果并重新决策；
4. `慈怀` 单独进入感染目标选择，允许感染下一步节点；
5. 其他随机效果先真实采样结算，再基于已确定的新状态选择路径；
6. 每次只从当前位面的当前精确状态补采，不读取后续地图；
7. 控制样本仅用于发现下游策略，最终候选比较使用新的等量样本和冻结贪心下游策略。

旧脚本的 `unlocked` 入口表示“首效果尚未出现”的事前评估：先完成六种等概率
效果条件的全部控制采样，再冻结同一版策略，用 `n_eval` 选择各条件动作，最后严格
用 `n_sim_trials` 独立评价整套条件策略；不会固定一次随机效果，也不会按候选数放大
最终评估预算。未显式传入 `n_eval` 时，它默认采用 `n_sim_trials`，避免用极少样本
选错条件动作后，再花大量预算反复验证已经选错的策略。

精确 DP 不再进入在线推荐，也不会向 MC 样本注入结果。

## 已修正的确定性错误

- Q 回报改成 `final_cd - decision_cd`，过去已经取得的 CD 不再污染未来动作价值。
- Q 使用在线 `count / total / total_sq`，不再只保留最近 200 条；增加到十万次确实会增加有效样本数，内存仍为每动作常数。
- cheat 在进入目标/路径阶段前立即扣除，路径样本不会混入错误的资源层。
- 浇灌和随机感染始终由环境采样，只有慈怀目标由玩家选择。
- 浇灌直接按每个感染源抽一个邻居，不再先生成笛卡尔积，单次效果复杂度由指数级降为 `O(活跃感染源数)`。
- 未看到随机效果时不再“预知六种结果中最好的一种”；重投后也不会提前给出路径。
- 慈怀无目标时按无效果继续，不会卡死；有目标时可选择所有未感染、未销毁节点，包括下一步节点。
- 推荐严格使用用户当前实际资源，不再把 0 次资源放大为 5/10 次。
- 平均最终 CD、胜率和界面当前 CD 使用同一初始 CD 口径。
- 三位面只继承上一图实际结算的 CD、cheat 和 reroll；下一图到达前不会加载或评价。
- 换图采用事务式提交：新图识别成功才替换当前会话，失败时保留原地图、历史和资源。
- 修改目标或 MC 样本参数会使旧请求失效并重采，旧目标胜率不会显示到新目标旁。
- 离线 `countdown_joint` 已把中间阈值放入资源分配转移，并修复必经负收益地图被当作 0 跳过的问题。

## 推荐与胜率的明确口径

主目标是**最大化平均最终倒计时**。目标 CD 只用于评估：

```text
胜率 = 最终实际 CD >= 目标 CD 的模拟次数 / 该候选独立模拟总次数
```

因此“推荐均分最高动作”和“胜率最高动作”可以不同。GUI 会把均分推荐画绿圈，把不同的最高胜率动作画金圈，并同时显示其均分。若产品以后要直接最大化达标率，策略状态必须加入“距离目标还差多少 CD”，这是另一种目标函数，不能只改排序文字。

## 时间与空间复杂度

设当前控制批次为 `N_c`，独立评价总批次为 `N_e`，一局平均决策数为 `L`，活跃感染源平均数为 `S`：

```text
时间：O((N_c + N_e) × L × S)
空间：O(实际访问到的状态-动作数)
```

空间不枚举全部 mask、资源组合或三图笛卡尔积；每个访问条目只保存常数个累计统计量。图扩大时成本随实际 rollout 覆盖增长，不会先做全状态 DP。不过，十万批次仍是十万次真实模拟，时间近似线性增长，GUI 因而使用后台线程、结构化进度和可取消任务。

### 十万级批次性能复盘

同一张第三位面测试图、`CD=0 / cheat=2 / reroll=3 / 目标=5` 下，`100000 + 100000`
配置实际执行 `199970` 条 rollout。优化前约 41.92 秒，优化后约 15.13 秒；`10000 +
10000` 从约 3.75 秒降到 1.46 秒。实际样本数没有缩减，首次大批次的渐进复杂度仍是
线性，只降低了每次决策的固定开销。

从战斗模拟中复用且适用于倒计时规则的做法是：

- 同一决策只构造一次规范状态键，并清掉已经销毁列的感染位；
- 冻结评价批次内缓存下游贪心动作，不在每条 rollout 中反复扫描同一动作集；
- 用位掩码保存未来节点和邻接节点，直接枚举置位节点，不建立全状态表；
- 预生成 24 种效果阶段合法动作组合，状态对象使用紧凑槽位；
- 控制批次复用连续随机流，候选公平评价通过恢复同一随机状态保留共同随机数；
- GUI 进度按墙钟节流，避免十万级短 rollout 产生大量跨线程信号。

没有复用战斗旧版的“几何重投压缩”。倒计时每次重投都会观察一个新效果，策略会根据
新效果和剩余资源重新决策；把连续失败合成一次随机变量会改变真实策略和结果分布。也没有
把十万改成提前停止的上限，因此当前提速不是少采样造成的。

## 仍然存在、不能伪装成已解决的限制

1. **MC 只有统计收敛，没有有限样本下的绝对最优保证。** 候选均值差小于标准误时应视为尚未分清，可继续增加当前状态样本。
2. **当前位面不可预知未来是有代价的。** 当前策略可能花掉对本图有益的资源；它无法知道未知后图是否更需要这些资源。这是信息边界，不是采样量能够解决的问题。
3. **三图标量 W 表不是完整随机转移。** 真正的跨图最优模型需要联合分布 `P(ΔCD, c_rem, r_rem)`；只用均值无法表达随机资源消耗和中间阈值达标概率。离线联合模块因此只是期望值近似，不参与当前 GUI 的在线策略。
4. **共同随机种子只能降低、不能消灭分支噪声。** 不同动作会消耗不同数量的随机数；若要严格逐事件配对，需要进一步实现按事件编号索引的随机 tape。
5. **识图结果仍决定地图模型质量。** 模板识别错误、漏边或感染标记错误会让 MC 精确地优化一张错误地图。GUI 会先展示识别结果和起点回退状态，便于人工发现。
6. **候选均值仍有轻微赢家偏差。** 同一批独立候选样本既用于选最高均值动作，也用于展示其均值；候选多、样本少时赢家显示值会略偏乐观。若要统计推断，应增加置信区间或另设报告批次。
7. **几何建图仍依赖经验阈值。** 列容差和右向连边距离适合当前截图尺度；分辨率或布局跨度显著变化时，应先校准识图/建图参数，而不是盲目增加 MC 批次。

## 旧实现为何停用

旧 `test/test_countdown_optimizer.py` 同时包含近似 DP、DP 热启动、MC、未来表、缓存和打印。审计确认它会：把随机结果取最大、错用重投资源层、混合 cheat 前后路径状态、自动读取后续典型图，并让 DP 在所谓 MC 推荐中长期优先。现在该文件只保留兼容入口，转发到 `tool/countdown_evaluator.py`；`ExactCountdownDP` 会明确报错，避免旧错误静默复活。
